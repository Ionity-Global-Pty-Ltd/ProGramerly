## 3.0.5 - one suite (supersedes the 2.3.0 notes below)

The direction was corrected on 2026-09-13: the Ionity tools are capabilities of
ProGramerly, not four separate programs. Fan control (Fanzi), the AiOS operator
layout and CiC are named on the site only; the MCP audit tool is a private side
tool for maintainers and is not mentioned publicly.

- Payload moved to the private repository `programerly-payload`
  (`programs-v1`). The Windows CI job fetches it with the repository secret
  `PAYLOAD_TOKEN` (fine-grained PAT, Contents: read-only on that repo) and
  packs it into `resources/programs`. `payload.download` is `false`, so the app
  never reaches for the network for these; a build without them shows the
  tiles as "not in this build".
- Download page rewritten as "One suite, not a folder of tools": names only,
  no download links, no hashes, no MCP. Release notes match.
- Local AI: `settings.aiDefaultModel = llama3.2:1b`; new catalogue item
  `ollama-small` (full + ai profiles); the Command Center offers one-click
  setup (install Ollama + model via the installer engine, or pull the model
  when Ollama is already running).
- Windows signing wired into the `windows` job: Azure Trusted Signing
  (`AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`,
  `AZURE_SIGNING_ENDPOINT`, `AZURE_SIGNING_ACCOUNT`, `AZURE_SIGNING_PROFILE`)
  or a classic `.pfx` (`WIN_CSC_LINK`, `WIN_CSC_KEY_PASSWORD`). The job prints
  the Authenticode status of every `.exe`. **The SmartScreen dialog only goes
  away once one of these is configured** - it is publisher reputation, not code.
- Version requested as "3.0.05"; shipped as the valid semver `3.0.5`.

## What changed in 2.3.0

**Command Center (Home tab).** Live CPU, memory, thermals, system disk and
network from the existing metrics service, a health line, a Ctrl+K command box
that finds any workspace or utility, a local-AI probe, and an Operations panel
(sync schedule, update state, managed package count).

**Kiosk mode.** Opt-in full-screen application shell, persisted in settings,
applied by the main process only on the explicit settings message, with a
visible Exit control and Ctrl+Shift+K. Not Windows Assigned Access.

**Bundled Ionity utilities - end to end.**

- `src/main/data/programs.json` is the single manifest (size + SHA-256 pins,
  payload repo/tag).
- `scripts/check-programs.js` validates the manifest, and hashes the payload
  folder when present (`--strict` makes it mandatory, `--write-sums` writes
  `SHA256-programs.txt`). Runs in the CI `validate` job.
- The CI `windows` job downloads the payload from the `programs-v1` release,
  verifies it, and electron-builder packs it into `resources/programs`. If the
  release is absent the installer still builds (with a warning) and the app
  falls back to download.
- `programs.js` stages from resources when bundled; otherwise downloads the
  one file from the release into a temporary name, byte-counts it, hashes it,
  and renames it into the managed folder. Progress streams to the Home tile
  via `programs:progress`. Verified again immediately before `shell.openPath`.
  Renderer input is only ever a catalogue id.
- The self-updater ignores tags that are not `v<semver>` so `programs-v1`
  can never be offered as an update.
- Download page section "Bundled Ionity utilities" with pins and live sizes.

**Release workflow fix.** `files:` listed `artifacts/SHA256.txt` twice (once
via `artifacts/**/*`). The duplicate upload raced itself, failed the step and
left the first v2.3.0 attempt as a draft without `SHA256.txt`. Fixed in
`60a2b38` (single glob, explicit `draft: false`); the release was re-published
by `workflow_dispatch` with `release_tag=v2.3.0`.

**Build machine fix.** Commits on G: were failing with
`fatal: failed to write commit object`. Root cause: the global git config has
`commit.gpgsign true` with an SSH signing key that is not loaded in
`ssh-agent`, so `ssh-keygen -Y sign` fails silently. This repository now has
`commit.gpgsign false` (repo-local only; the global setting is untouched).
Load the key into the agent (`ssh-add`) and remove the local override to sign
again.

   Then `gh workflow run build.yml --repo Ionity-Global-Pty-Ltd/ProGramerly -f release_tag=v3.0.5`

   `185.199.108.153`, `.109.153`, `.110.153`, `.111.153` replacing the "Parked"
   record. Then Enforce HTTPS in Settings -> Pages. Until then the Pages URL
   redirects to the registrar lander.

   Signing (or buy an OV/EV Authenticode certificate) and add the secrets above.
4. **v2.2.1 stray assets:** `gh release delete-asset v2.2.1 app.log --yes` and
   the same for `screenshot.png`.

   `firebase deploy --only firestore:rules,storage`.
