What it actually does

No wizards to babysit, no half-finished PATH. Pick a profile, press go, walk away.

A real catalogue

Over a hundred curated packages across runtimes, IDEs, shells, databases, embedded, ML and MCP tooling — resolved to winget, Chocolatey or Homebrew per machine.

Stays current

Checks GitHub Releases on its own schedule, verifies each download against the published SHA-256, and updates itself in place.

Watches the machine

A tray monitor for CPU, memory, disk and network, with live probing so you find out something broke before your build does.

Repairs itself

Registry repair, PATH reconstruction and a dry-run mode that shows exactly what would change before a single byte moves.

AEDi, on first run

Tick AEDi local core in Software and Ollama plus a starter model are installed with everything else. The chip in the top bar always says which model is answering — or that none is yet. Nothing leaves the machine.

Zero runtime dependencies

Node standard library only. Nothing to audit but the code you can already read, under Policy 986 AED.

The Ai-OS shell and the DOME

ProGramerly opens in the IONITY Ai-OS operator layout: one ask box wired to AEDi, the workstation DOME — five strata, 26 segments, drillable — stats, tiles and a dock. Every percentage on the dome says whether it is measured, computed, an assessment or state; nothing is scored from a constant.

Ionity, in motion

Native AI on the edge, the AEDi stack, and the workstation that runs it — twenty seconds from the Ionity brand film.

New in 3.6 — the forecast, and the catalog people actually live in

AEDi Predict tells you how the run will go on this machine before you press Install — and learns from every run. Twenty-seven new items, three new groups, and still not one account linked.

AEDi Predict

Likelihood per item, expected clean installs, minutes with a range, download against free disk and an 8 GB reserve, and a risk list — built from what is read at that moment: engines on PATH, package hosts that answer, free space, elevation. Every figure carries its class: measured, learned, computed, assumed.

It learns this machine

Every run teaches its outcomes and timings back in. The likelihood is a shrunk posterior — three real outcomes outweigh the shipped prior — minutes switch to the learned median, and a speed factor scales the priors to your line. One sample every five minutes gives each disk a GB/day trend and a days-to-full. Nothing leaves the machine; Forget the history is one click.

Communication

WhatsApp Desktop, Microsoft Teams, Zoom, Slack, Discord, Telegram, Signal — installed and left signed out. You link your own phone and accounts; ProGramerly never touches one.

Cloud drives and sync

Google Drive for desktop, Microsoft OneDrive, Dropbox, and rclone for scripting any of them from the terminal. Same rule: installed, not signed in.

GitKraken, lazygit, PowerToys, LibreOffice, Bruno, Twilio CLI, n8n. archify from the public Ionity fork, installed as an agent skill.

Verified on the real application

The engine has 14 checks with injected facts; the running app has 39 more — the forecast line in Software, the four stat tiles, a likelihood bar per item under a strict CSP, ten hosts probed, a suggestion added to the selection, an honest answer when no model runs. Downloads

Every build is produced on GitHub's own runners — Windows on windows-latest, macOS on Apple's toolchain, Linux on ubuntu-latest — and published with a SHA256.txt you can check before you run anything.

Builds are currently unsigned: Windows shows “Windows protected your PC” → More info → Run anyway, and macOS asks for right-click → Open the first time. On Linux nothing gets in your way — mark the AppImage executable with chmod +x and run it, or install the package with sudo apt install ./programerly_*_amd64.deb / sudo dnf install ./programerly-*.rpm. Signing turns on automatically the moment the certificates are added to the repository secrets.
